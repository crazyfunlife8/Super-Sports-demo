## 二、方案 A：部署至 Netlify（建議）

### 前置需求
- Netlify 帳號（免費方案即可）
- Git 儲存庫（GitHub / GitLab / Bitbucket）或直接拖曳部署

### 方法 1：拖曳資料夾部署（最快）

1. 前往 [https://app.netlify.com](https://app.netlify.com)，登入帳號
2. 點擊「**Add new site**」→「**Deploy manually**」
3. 將整個專案資料夾（`賽事投注展示平台/`）**拖曳**至上傳區域
4. 等待 30 秒部署完成
5. 取得自動分配的網址（例：`https://super-sports-demo.netlify.app`）

> **注意**：此方法每次更新需重新拖曳，適合一次性交付。

### 方法 2：連結 Git 儲存庫（推薦，可持續更新）

1. 將專案推送至 GitHub：
   ```bash
   git init
   git add .
   git commit -m "initial commit"
   git remote add origin https://github.com/{你的帳號}/{repo名稱}.git
   git push -u origin main
   ```

2. 前往 Netlify → 「**Add new site**」→「**Import an existing project**」

3. 選擇 GitHub，授權後選取對應 repo

4. 部署設定：

   | 設定項 | 值 |
   |-------|----|
   | Branch to deploy | `main` |
   | Base directory | （留空） |
   | Build command | （留空） |
   | Publish directory | `.`（根目錄）|

5. 點擊「**Deploy**」，等待完成

6. 日後更新只需 `git push`，Netlify 自動重新部署

### Netlify 自訂網域（選用）

1. Netlify → 你的 site → **Domain management** → **Add a domain**
2. 輸入業主自有網域（例：`sports.example.com`）
3. 依指示在 DNS 服務商新增 CNAME 記錄指向 Netlify
4. 等待 DNS 生效（最長 24 小時），Netlify 自動申請 SSL 憑證

## 三、方案 B：部署至業主自有主機（Nginx / Apache）

### 需求
- Linux 主機（Ubuntu 20.04+ 建議）
- Nginx 或 Apache
- 可選：SSL 憑證（Let's Encrypt 免費）

### Nginx 設定範例

1. 將專案資料夾上傳至主機（scp 或 FTP）：
   ```bash
   scp -r 賽事投注展示平台/ user@your-server:/var/www/sports-demo
   ```

2. 建立 Nginx 設定檔：
   ```nginx
   # /etc/nginx/sites-available/sports-demo
   server {
       listen 80;
       server_name sports.example.com;
       root /var/www/sports-demo;
       index index.html;

       location / {
           try_files $uri $uri/ /index.html;
       }

       # 靜態資源快取
       location ~* \.(css|js|png|jpg|gif|ico)$ {
           expires 7d;
           add_header Cache-Control "public, no-transform";
       }
   }
   ```

3. 啟用設定並重啟：
   ```bash
   ln -s /etc/nginx/sites-available/sports-demo /etc/nginx/sites-enabled/
   nginx -t
   systemctl reload nginx
   ```

4. 申請 SSL（選用）：
   ```bash
   apt install certbot python3-certbot-nginx
   certbot --nginx -d sports.example.com
   ```

### Apache 設定範例

```apache
# /etc/apache2/sites-available/sports-demo.conf
<VirtualHost *:80>
    ServerName sports.example.com
    DocumentRoot /var/www/sports-demo
    <Directory /var/www/sports-demo>
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

```bash
a2ensite sports-demo
systemctl reload apache2
```

## 四、方案 C：Windows IIS（業主為 Windows Server）

1. 安裝 IIS（控制台 → 程式與功能 → Windows 功能 → Internet Information Services）

2. 在 IIS 管理員新增網站：
   - 實體路徑：指向專案資料夾
   - 繫結：設定 IP 與 port（預設 80）

3. 確認 `index.html` 已加入預設文件清單

4. 設定靜態內容 MIME 類型（若缺失）：
   - `.json` → `application/json`
   - `.woff2` → `font/woff2`

## 五、部署前檢查清單

### Supabase 確認項目

- [ ] `matches` 表已建立，RLS 政策正確（見 Supabase 設定文件）
- [ ] `tickets_aggregate` 表已建立（含 unique constraint）
- [ ] `sites` 表已建立
- [ ] `display_settings` 表已建立，Realtime 已啟用
- [ ] Edge Function `sync-matches` 已部署，環境變數 `SPORTSGAMEODDS_API_KEY` 已設定
- [ ] Anon Key 與 Project URL 正確填入 `js/supabase-client.js`

### 程式碼確認項目

- [ ] `js/supabase-client.js` 中的 `SUPABASE_URL` 與 `SUPABASE_ANON_KEY` 確認正確
- [ ] 所有 HTML 頁面的 CSS / JS 路徑以 `/` 開頭（絕對路徑），在子路徑下部署需調整

> **路徑注意**：若部署在子目錄（例：`example.com/sports/`），需將 HTML 中所有 `/css/…`、`/js/…` 改為相對路徑 `css/…`、`js/…`，或在 Netlify 設定 `base` 路徑。

### 功能驗證項目

- [ ] 三個頁面均可正常開啟，無 404
- [ ] 首頁業績表格正常顯示（有資料 or 空白都算正常）
- [ ] 即時注單頁倒數計時正常運作
- [ ] 歷史賽事頁有賽事列表
- [ ] 進入 `index.html?edit=true` 出現編輯模式面板
- [ ] 跑馬燈正常捲動
- [ ] 瀏覽器主控台（F12）無紅色錯誤訊息

## 六、Supabase Edge Function 部署

Edge Function 需用 Supabase CLI 部署，與前端網站部署分開處理。

### 安裝 Supabase CLI

```bash
# macOS
brew install supabase/tap/supabase

# Windows（PowerShell，需 scoop）
scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
scoop install supabase

# npm（跨平台）
npm install -g supabase
```

### 登入與連結專案

```bash
supabase login
supabase link --project-ref igavhfxwfsuyksnzbvfx
```

### 設定 API 金鑰環境變數

```bash
supabase secrets set SPORTSGAMEODDS_API_KEY=your_api_key_here
```

### 部署 Edge Function

```bash
supabase functions deploy sync-matches
```

部署成功後，Edge Function 端點為：
```
POST https://igavhfxwfsuyksnzbvfx.supabase.co/functions/v1/sync-matches
```

## 七、更新維護

| 更新類型 | 操作方式 |
|---------|---------|
| 前端程式碼（HTML/CSS/JS） | 重新上傳/推送，Netlify 自動重新部署 |
| Supabase 資料 | 直接在 Supabase Dashboard 操作，或透過編輯模式 |
| Edge Function | 修改 `index.ts` 後重新執行 `supabase functions deploy sync-matches` |
| API 金鑰更換 | `supabase secrets set SPORTSGAMEODDS_API_KEY=新金鑰` |
| 前端 Supabase 金鑰更換 | 修改 `js/supabase-client.js` 後重新部署前端 |
